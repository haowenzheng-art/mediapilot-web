# MediaPilot 产品需求文档（PRD）

> 版本：v3  
> 更新日期：2026-06-26  
> 状态：Phase 2 进行中

---

## 1. 产品定位

**一句话**：新媒体人一站式提效工具，从发现热点到创作内容全流程自动化。

**核心价值主张**：解决新媒体人日常工作中"链路断裂"的痛点——热点、文案、脚本、素材散落在不同工具里，互相不通。MediaPilot 用「热点」这条主线把整个创作链路串成一条流水线。

```
发现热点 → 生成文案/脚本 → 制作视频 → 发布内容
```

---

## 2. 用户画像

| 画像 | 痛点 | 核心诉求 |
|------|------|----------|
| 短视频运营 | 每天花 2 小时刷热点、找选题 | 一键聚合全网热点，按热度排序 |
| 口播博主 | 写文案卡壳，没有灵感框架 | 给个话题和人设就能出完整口播稿 |
| 内容团队 | 文案/脚本/素材散落，复盘困难 | 所有产出自动入库，可追溯热点来源 |
| 新媒体新手 | 不知道怎么拍、怎么写 | 拍摄脚本直接给分镜头，照着拍就行 |

---

## 3. 核心场景

### 场景 A：追热点出内容（黄金路径）
1. 早上打开 MediaPilot，热点搜索页看到今日热榜（带 `today` 徽章）
2. 选中一个热点 → 一键生成口播文案（热点框架模式）
3. 文案不满意 → 点"再改改"（更口语化/加情绪/加观点）
4. 满意后 → 生成拍摄脚本（选抖音/小红书/B站 × 激情/轻松/专业）
5. 所有产出自动入库，热点反查能追溯这条热点催生了哪些内容

### 场景 B：订阅话题自动推送
1. 订阅"AI Agent"话题，频率每日
2. 每日 08:00 调度器自动扫描新热点
3. 推送记录入库，未读数 badge 提醒
4. 用户点推送 → 直接跳转生成文案

### 场景 C：音视频转文字
1. 上传录音/视频文件
2. Whisper 本地转写，返回时间轴 + 大纲
3. 文字可复制、可跳转生成文案

## 4. 功能需求

### 需求 1：全网热点搜索（P0，已完成）

**用户故事**：作为短视频运营，我想按关键词搜全网热点，按热度排序，这样我不用挨个平台刷。

**功能点**：
- 按关键词 + 时间范围（1/3/7/30 天）搜索
- 五端聚合：百度新闻、微博热搜、知乎热榜、抖音热榜、小红书
- 每条热点带：标题、热度值、趋势方向（up/down/same）、摘要、原文链接、配图
- `is_today` 徽章：发布日期是今天则自动标记
- AI 总结：选中热点一键生成深度摘要
- 文章内容抓取：按来源走不同解析器
- 导出 CSV

**端点**：
- `POST /api/v1/trending/search`
- `POST /api/v1/trending/summary`
- `POST /api/v1/trending/article/content`
- `GET /api/v1/trending/export`

**数据源**：网页抓取（不依赖付费 API），各平台有独立爬虫模块，`60s-api.viki.moe` 作为部分平台 fallback。

---

### 需求 2：话题订阅与自动推送（P1，已完成）

**用户故事**：作为内容创作者，我想订阅感兴趣的话题，系统每天帮我盯新热点，这样我不会错过。

**功能点**：
- 创建订阅（扣配额、拒绝重复话题）
- 频率：每日 / 每 3 天
- 调度器：每日 08:00 扫描到期订阅（`next_push_at <= now`），调热点搜索，写推送记录，推进下次推送时间
- 暂停 / 恢复 / 删除
- 推送记录：未读数 badge、`unread_only` 筛选、标记已读
- 用户隔离（A 看不到 B 的订阅）

**端点**：
- `GET/POST /api/v1/subscriptions`
- `PUT/DELETE /api/v1/subscriptions/{id}`
- `POST /api/v1/subscriptions/{id}/pause` / `resume`
- `GET /api/v1/subscriptions/push/records`
- `POST /api/v1/subscriptions/push/records/{id}/read`
- `GET /api/v1/subscriptions/push/unread-count`

---

### 需求 3：口播文案生成优化（P0，已完成）

**用户故事**：作为口播博主，我想给个话题和人设就能出完整口播稿，不用从零开始写。

**功能点**：
- 三模式：
  - 从0到1：话题 + 人设 → 文案
  - 热点框架：热点介绍/总结 + 人设 → 文案
  - 改写：复制文案 + 人设 → 洗稿重写
- 人设系统：存储最近 3 次输入的人设，快捷选取
- "再改改"：更口语化 / 加情绪 / 加观点
- 输出格式：标题 + 钩子（2-3 备选）+ 文案主体
- AI 内容规范：禁止 # 符号、去 AI 感、格式工整

**端点**：
- `POST /api/v1/copywriting/generate`
- `GET /api/v1/copywriting/personas`

---

### 需求 4：拍摄脚本生成（P0，已完成）

**用户故事**：作为新手，我想直接拿到分镜头脚本，照着拍就行，不用自己想画面。

**功能点**：
- 三平台 × 三风格矩阵：
  - 平台：抖音（60s 竖屏 5 镜头）/ 小红书（3min 竖屏 8 镜头）/ B站（5-10min 横屏 15 镜头）
  - 风格：energetic 激情热血 / relaxed 轻松幽默 / professional 专业分析
- 输出：标题 + 钩子 + 分镜头脚本（编号/时长/画面/台词/场景/运镜）+ 行动号召 + 标签
- 导出：json / txt / csv
- 自动入库（关联热点 ID）

**端点**：
- `POST /api/v1/shoot-script/generate`
- `GET /api/v1/shoot-script/{id}`
- `POST /api/v1/shoot-script/export`

---

### 需求 5：内容关联与追踪（P1，已完成）

**用户故事**：作为团队负责人，我想看到一条热点催生了哪些文案和脚本，这样我能复盘哪些热点值得追。

**功能点**：
- 内容库：文案/脚本生成时自动登记入库（`user_id` / `content_type` / `hot_topic_id`）
- 热点反查：给 `hot_topic_id` 返回它催生的所有内容
- 话题趋势历史：每条热点按时间累积热度记录，可看曲线判断涨跌
- 用户隔离

**端点**：
- `GET/POST/PUT/DELETE /api/v1/content-library/contents`
- `POST /api/v1/content-library/contents/{id}/process`
- `GET /api/v1/content-library/hot-topic/{hot_topic_id}/contents`
- `POST /api/v1/content-library/topic-history`

---

### 需求 6：音视频转写（P1，已完成）

**用户故事**：作为博主，我想把录音/视频转成文字，这样我能快速整理素材。

**功能点**：
- 上传音视频文件（mp3/wav/m4a/aac/mp4/mov）
- Whisper 本地转写，返回逐字稿 + 时间轴 + 大纲
- 异步任务：上传返回 task_id，轮询状态
- 配额扣减（transcribe_audio / transcribe_video 各 10）
- 失败退还配额

**端点**：
- `POST /api/v1/media/upload`
- `GET /api/v1/media/task/{task_id}`

**已知限制**：
- Whisper 为 CPU 本地推理，长视频耗时；线上可配 `USE_VOLCENGINE_ASR=true` 走火山 ASR
- 转写完成后立即返回 transcript + 默认大纲，AI 大纲生成不再阻塞结果

---

### 需求 7：视频分析（P2，部分完成）

**用户故事**：作为博主，我想分析 B站视频的逐字稿，学习别人怎么讲。

**功能点**：
- 粘贴视频链接，获取视频信息（标题/封面/播放/点赞）
- 提取逐字稿（yt-dlp 下载音频 + Whisper 转写）
- 完整文本 / 时间轴双视图

**当前限制**：
- 暂仅支持 **B站中文视频**
- 英文视频强制中文转写效果差（待修复）
- 失败回退 mock 数据（待移除，改为明确报错）

**端点**：
- `POST /api/v1/video/fetch`
- `POST /api/v1/video/transcript`

---

### 需求 8：AI 产品导师（P2，已完成）

**用户故事**：作为新用户，我不知道产品每个功能怎么用，我想问 AI 直接得到答案和跳转。

**功能点**：
- YAML 知识库（11 条 FAQ）
- 关键词匹配命中 → 返回答案 + `action_url` 跳转按钮
- 未命中 → LLM 兜底（带 KB 摘要作 RAG 上下文）
- LLM 不可用 → 固定 fallback 文案

**端点**：
- `POST /api/v1/ai/tutor`
- `GET /api/v1/ai/tutor/faqs`

---

### 需求 9：工程化基础设施（v3，已完成）

- **认证**：JWT access + refresh token，`/auth/refresh` 自动续期
- **配额**：每个功能不同配额成本，扣减 / 退还 / 检查
- **限流**：按端点配置 rate limit
- **异步队列**：Redis + ARQ，文案/热点后台生成
- **调度器**：APScheduler，订阅推送 + Token 清理
- **请求链路**：`req_id` 贯通日志
- **数据看板**：`/api/v1/analytics/dashboard` 真实用户活动
- **发布日历**：`/api/v1/calendar/events` CRUD
- **偏好设置**：`/api/v1/user/preferences` 主题/语言/默认平台
- **Sentry**：可选接入

## 5. 非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | 热点搜索 ≤ 10s，文案生成 ≤ 30s，转写按音频时长 |
| 可用性 | Redis 不可用时降级（队列任务暂停，API 可用） |
| 安全 | JWT 鉴权，用户隔离，`.env` 不入库 |
| 可观测 | `req_id` 贯通，Sentry 异常上报，访问日志 |
| 可测试 | e2e 测试覆盖核心链路，≥132 通过 |
| 数据库 | SQLite（开发）/ PostgreSQL（生产），Alembic 迁移 |
